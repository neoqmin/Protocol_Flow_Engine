# 위협 모델 · 키 관리 · 라이선스 원칙

초안. MVP-A 시작 전에 리뷰하고 확정한다. 법률 관련 내용은 자문이 아니며 배포 전 법무 검토가 필요하다.

## 1. 보호 대상 (Assets)

- 터널로 전달되는 사용자 트래픽의 **기밀성·무결성**
- 세션 키, 사설키, 인증서 자격
- 엔진의 가용성 (파서/상태머신이 악성 입력으로 죽지 않을 것)
- (Post-MVP) 배포되는 Flow 정의의 무결성

## 2. 공격자 모델

| 공격자 | 능력 | MVP 대응 |
|---|---|---|
| 네트워크 수동 관찰자 | 패킷 캡처 | TLS 1.3 + tls-crypt + AES-GCM |
| 네트워크 능동 공격자 | 패킷 변조/삽입/재생/드롭 | AEAD 검증, replay window, 제어 채널 reliability + tls-crypt HMAC |
| 악성/비정상 peer | 잘못된 형식·거대 메시지·상태 위반 | 엄격한 파서, 길이 상한, 상태머신 검증, fuzzing |
| 로컬 비특권 프로세스 | 메모리/파일/소켓 접근 시도 | 키 파일 권한, 메모리 zeroization, 로그에 비밀 금지 |
| 중간 노드(프록시/Relay, Post-MVP) | 트래픽 관찰/차단/조작 | **신뢰하지 않음**: 종단 간 암호화, Relay는 키를 갖지 않음 |

비목표(Non-goals): 호스트가 완전히 장악된 상황, 하드웨어 사이드채널, 트래픽 분석(길이/타이밍) 방어.

## 3. 신뢰 경계

```text
[네트워크] ──(비신뢰)── [Transport] ── [Parser/Crypto Block] ── [Key Manager] ── [TUN/앱]
                                         ↑ 모든 입력은 여기서 검증      ↑ 비밀은 이 안쪽에만
```

- Transport 이후 첫 Block(파서)부터 모든 입력을 **비신뢰 데이터**로 취급한다.
- 비밀(키)은 Key Manager 안에서만 보관한다. Flow/Block 설정·로그·오류 메시지·테스트 golden에 나타나지 않는다.

## 4. 키 관리

| 항목 | 규칙 |
|---|---|
| Key Reference | Flow/Block은 키 값이 아니라 **불투명 핸들(Key Reference)** 만 다룬다 |
| 저장 | 사설키/인증서: 플랫폼 저장소(Keychain, Android Keystore, Windows DPAPI/CNG, Linux 파일 권한/키링). 세션 키는 메모리만 |
| Zeroization | 세션 키·중간 키 재료는 사용 후 즉시 지운다 (`explicit_bzero`, `SecureZeroMemory` 등 컴파일러가 제거하지 않는 방식). 테스트로 검증 |
| 수명 | 재협상 주기를 강제한다. AEAD packet-id가 고갈(랩어라운드)되기 **전에** 반드시 새 키로 전환하고, 불가능하면 연결을 종료한다 (nonce 재사용 금지) |
| 난수 | OS CSPRNG만 사용 (자체 PRNG 금지) |
| 비교 | MAC/태그 비교는 상수 시간 |
| 노출 금지 | 키는 DSL/Flow JSON/로그/크래시 덤프/테스트 벡터에 평문으로 남기지 않는다. 개인 키 커밋 금지 |
| 암호 라이브러리 | 자체 구현 금지. 검증된 라이브러리(OpenSSL/BoringSSL 등)를 수정 없이 링크 (Provider 인터페이스 뒤에 둔다). 모바일 선택은 PM-1에서 확정 |

## 5. 보안 개발 요구사항

- 모든 파서/디코더에 **fuzz 타깃 또는 전수 테스트**를 둔다 (현재: 헤더 파서 전수 테스트 + libFuzzer 타깃).
- CI에 ASan/UBSan 잡 유지. 새 코드는 `-Werror` 통과.
- 길이/개수 필드는 상한을 두고 정수 오버플로를 검사한다.
- 보안에 영향을 주는 결정(nonce 구성, 재협상 정책)은 `docs/DECISIONS.md`에 기록하고 테스트로 고정한다.
- 서명되지 않은/검증 안 된 Flow를 보안 경로에 로드하지 않는다 (PM-7 이후 상세화).

## 6. 라이선스 / Clean-room 원칙

- 독립 구현(D-006)은 GPL 코드와의 링크 문제를 피할 수 있으나, **OpenVPN 소스를 보고 옮기면 파생 저작물 논란**이 생길 수 있다. 따라서:
  - 구현 근거는 공개 문서·RFC·pcap 관찰로 한정한다 (`docs/OpenVPN_Interop_Profile.md` §5).
  - 소스에서 가져온 코드 조각·구조를 복사하지 않는다. 의심되는 경우 기록하고 리뷰한다.
- **iOS/App Store 배포**: GPL 코드를 앱에 포함하는 것은 배포 약관과 충돌한 전례가 있으므로, iOS 빌드에는 GPL 코드를 포함하지 않는다. 의존성 라이선스를 `third_party/README.md`에 기록하고 CI에서 목록을 점검한다.
- OpenVPN 바이너리/DCO 모듈은 **테스트 상대 또는 별도 프로세스로만** 사용하고 우리 바이너리에 링크하지 않는다.

## 7. 성능·자원 목표 (잠정)

> 수치는 **기준선 측정 후 확정**한다. 지금은 측정 방식만 정한다.

| 항목 | 방식 |
|---|---|
| 처리량/지연 | 같은 장비에서 OpenVPN 2.6 유저 모드와 비교 (기준선 = 100%). 목표 비율은 MVP-A 종료 시 설정 |
| 메모리 | iOS Network Extension 한도(약 50MB) 내에서 **여유 포함 상한**을 PM-1 진입 시 정함 (잠정: 한도의 절반 이하) |
| 바이너리 크기 | 모바일 빌드 기준으로 측정 기록 |
| 배터리 | 모바일 단계(PM-1)에서 keepalive/wakeup 빈도로 측정 |
